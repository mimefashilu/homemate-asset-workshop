# 内置 AHM 资源读写

从 v0.4.0 起，工坊使用项目自己的 `homemate_workshop/ahm_codec.py`，不需要用户安装、寻找或指定 PPExtractor。源码及便携包均不包含该第三方 EXE。

## 实现范围

- AHM 正式资源包的目录结构使用项目已有的 PP 目录解析、头变换和重建代码。
- 成员数据按四个小端 16 位 XOR 字处理，各字按固定步进模 65536 演进。每个成员重新开始；最后不足一个 16 位字的单字节保持原值。
- 使用固定大小分块，避免一次加载整个游戏包。编码与解码是同一变换。
- `.ema` 图片包保留前八字节不透明信息及原扩展名，图片提取后供 Pillow 使用。编辑已有 EMA 时原始封装头保留不变；从新图片创建 EMA 时使用规范的零头。
- 支持范围仅为本项目已验证的 AHM 资源；不自动猜测其他 Illusion PP 变种。

该模块通过自己生成的已知字节序列进行黑盒观察后独立编写，没有引入 PPExtractor 的二进制或源码，也没有复制未知许可的第三方编解码实现。

## 交叉验证

开发者如已有历史参考工具，可将其保留在自己的游戏 data 目录，用 `HM_TEST_GAME_DIR` 指定位置后运行集成测试。参考 EXE 仅用于可选的开发比对：

1. 生成空文件、1–41 字节、块边界、周期边界、超过 1 MB 的文件以及 EMA BMP/TGA 图片。
2. 比较普通成员的密文字节，以及两个实现互相解码后的完整文件。
3. 从本机 16 个可解析资源包中构建小型副本，比对 105 个成员、22 种扩展名的解码结果，包含约 22 MB 的模型成员。
4. 使用内置后端进行贴图、模型、备份与恢复测试；原游戏不是写入目标。

参考工具在创建 EMA 时，前八字节元数据存在非确定性；因此生成 EMA 的比对检查图像主体，并单独验证工坊保留已有元数据的行为，不把这些不稳定字节当作必须复现的格式规则。

普通用户运行工具不需要上述参考 EXE。默认核心测试使用程序生成的数据，无需游戏资源；只有可选参考比对需要自己已有的外部程序。
